# 零售销售数据分析项目（Retail Sales Analysis）

> 本项目基于**公开开源零售数据集**进行练习，在复现原版项目基础 SQL 指标的基础上，**自主拓展了 5 项运营指标分析**（月度环比、用户复购、用户消费分层、品类客单价、品类毛利率），用于数据运营实习生岗位求职展示。

---

## 项目背景

本项目是一份求职练习项目，使用一份公开的零售订单练习数据（`Retail_Sales.csv`，共 2,000 条订单记录），完成「数据探查 → 数据清洗 → SQL 取数 → 可视化 → 业务解读」的完整分析流程。

> **诚实声明**：本项目不涉及任何企业真实业务、内部数据、脱敏数据或隐私数据；不编造任何公司名称或业务场景；所有分析结论**仅针对本练习数据集**，不可直接套用于真实商业环境。

---

## 项目目标

证明求职者具备数据运营实习生岗位所需的核心能力：

1. **数据校验与清洗**：能发现数据中的拼写错误、缺失值、格式不一致、负毛利订单等质量问题，并说明清洗理由；
2. **SQL 取数**：能使用 pandasql（SQLite 语法）完成指标计算；
3. **运营指标理解**：理解环比、复购、用户分层、客单价、毛利率等核心运营指标的口径；
4. **业务翻译**：能把数据结果转化为具体、可落地的运营建议，而非空洞话术。

## 分析流程

1. **数据读取与探查**：查看形状、字段类型、前 15 行样本、描述性统计、缺失值统计；识别 sales=0 的取消订单、负毛利订单等异常；
2. **数据清洗**：修正列名拼写（`quantiy` → `quantity`）、规范时间格式、剔除缺失记录、过滤异常订单（sales ≤ 0）；
3. **基础指标复现**：复现原版 10 个 SQL 业务问题（并修正原版中 `quantity > 10` 等与数据不符、时段边界重叠等问题）；
4. **自主拓展分析**：月度环比、用户复购、用户消费分层、品类客单价、品类毛利率，每项「SQL + 可视化 + 三段式解读」；
5. **结论与局限**：汇总业务结论，说明局限与后续优化方向。

---

## 核心业务发现（仅针对本练习数据集）

1. **整体规模**：有效订单 1,987 笔，总销售额 908,230 元，155 位客户，整体客单价约 457 元。
2. **品类结构均衡**：Electronics / Clothing / Beauty 三品类收入接近，客单价 Beauty 最高（469.38 元）、Clothing 最低（444.12 元）。
3. **明显季节节奏**：每年 9 月起量、12 月冲顶、1 月回落（2022-09 环比 +192.4%、2023-01 环比 -66.9%）。
4. **收入依赖头部与高频用户**：深复购用户（≥10 次，88 人）贡献 78.3% 销售额；高价值用户（前 20%，31 人）贡献 44.8% 销售额，呈典型"二八分布"。
5. **毛利率分化**：整体毛利率 46.39%，Beauty 最高（47.92%）、Electronics 最低（45.17%）；另有约 15.6% 的订单成本高于售价（负毛利），需排查是录入异常还是清仓策略。
6. **时段集中**：晚间订单占绝对主力（1,275 单），下午最少（164 单）。

## 项目局限性

1. 数据为公开练习数据，结论仅用于方法论演示，不能直接套用于真实商业环境；
2. 无商品、渠道、促销字段，无法做单品/渠道/活动归因；
3. 时间粒度仅到小时，且 1–8 月样本量偏少，环比数字波动较大；
4. 复购分析只能按"累计次数"近似，无法精确到复购周期。

---

## 后续优化方向

1. 引入 **RFM**（最近一次消费 / 频次 / 金额）做更精细的用户分层；
2. 深化**成本分析**：排查 309 笔负毛利订单（cogs > 售价）是录入异常还是经营策略，并把毛利细化到单品级；
3. 增加商品级、周维度的向下钻取，定位具体 SKU 与促销节奏；
4. 若获得真实数据，可开展 A/B 实验、漏斗转化等运营专项分析。
